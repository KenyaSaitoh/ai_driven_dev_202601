# 要件定義書 - berry-books-api（オンライン書店バックエンドサービス）

プロジェクトID: berry-books-api  
バージョン: 2.0.0  
最終更新日: 2025-12-27  
ステータス: REST API仕様確定

---

## 1. プロジェクト概要

### 1.1 構築するもの

berry-books-apiは、オンライン書店「Berry Books」のバックエンドサービスとして機能するREST APIアプリケーションです。注文管理という独自のドメインを持ち、フロントエンド（berry-books-spa）の唯一のエントリーポイントとして、JWT認証、注文処理、外部API連携などのEC機能をREST APIとして提供します。

### 1.2 プロジェクトの目的

本システムは、フロントエンド（React SPA等）から利用されるバックエンドAPIを提供し、以下を実現することを目的とします：

* 注文管理ドメイン: 注文データの永続化と管理
* 外部API連携: 複数のバックエンドAPI（back-office-api、customer-hub-api）を呼び出し
* API-First開発: 明確なAPI仕様に基づく開発
* JWT認証: ステートレスな認証機構による水平スケーラビリティ
* ビジネスロジック: 注文処理、配送料金計算などの実装

## 4. 対象業務・対象外業務

### 4.1 対象業務

#### 4.1.1 認証・認可業務

SCOPE-001: システムは、新規顧客登録機能をREST API経由で提供しなければならない。

SCOPE-002: システムは、ログイン・ログアウト機能（JWT発行・無効化）を提供しなければならない。

SCOPE-003: システムは、JWT検証とユーザー情報取得機能を提供しなければならない。

#### 4.1.2 書籍管理業務

SCOPE-004: システムは、書籍一覧取得、書籍詳細取得、カテゴリ別検索、キーワード検索機能を提供しなければならない。

SCOPE-005: システムは、カテゴリ一覧取得機能を提供しなければならない。

SCOPE-006: システムは、書籍表紙画像配信機能を提供しなければならない。

#### 4.1.3 注文管理業務

SCOPE-007: システムは、注文作成機能（在庫引き当て含む）を提供しなければならない。

SCOPE-008: システムは、注文履歴取得、注文詳細取得機能を提供しなければならない。

SCOPE-009: システムは、在庫の自動減算機能を提供しなければならない。

SCOPE-010: システムは、楽観的ロックによる並行制御を実装しなければならない。

#### 4.1.4 配送料金計算業務

SCOPE-011: システムは、購入金額に応じた配送料金の自動計算機能を提供しなければならない。

SCOPE-012: システムは、配送先地域（沖縄県）に応じた料金算定機能を提供しなければならない。

### 4.2 対象外業務

OUT-OF-SCOPE-001: システムは、ユーザーインターフェースの提供、画面遷移制御、クライアントサイドバリデーションを対象外とする（別のReactアプリが担当）。

OUT-OF-SCOPE-002: システムは、書籍マスタの登録・更新・削除、在庫の補充処理、出版社・カテゴリマスタの管理を対象外とする。

OUT-OF-SCOPE-003: システムは、実際の決済処理（クレジットカード決済連携、銀行振込の入金確認）を対象外とする（決済方法の選択のみ実装）。

OUT-OF-SCOPE-004: システムは、配送業者への配送依頼、配送状況の追跡、配送完了の通知を対象外とする。

OUT-OF-SCOPE-005: システムは、メールマガジン配信、クーポン・キャンペーン管理、レビュー・評価管理を対象外とする。

## 5. 機能要件（EARS記法）

### 5.1 認証API（/api/auth）

#### 5.1.1 ログイン

FR-AUTH-001: WHEN 顧客が有効なメールアドレスとパスワードを送信したとき、システムはJWTトークンを生成し、HttpOnly Cookieとしてレスポンスに設定しなければならない。

FR-AUTH-002: WHEN ログイン処理中、システムはパスワードをBCryptアルゴリズムで検証しなければならない。

FR-AUTH-003: WHERE 開発環境で平文パスワードが使用されている場合、システムは平文比較による認証をサポートしなければならない。

FR-AUTH-004: IF メールアドレスが存在しない、またはパスワードが一致しない場合、THEN システムは401 Unauthorizedエラーを返し、"メールアドレスまたはパスワードが正しくありません"というメッセージを表示しなければならない。

FR-AUTH-005: IF メールアドレスまたはパスワードが空の場合、THEN システムは400 Bad RequestエラーとBean Validationエラーメッセージを返さなければならない。

#### 5.1.2 ログアウト

FR-AUTH-006: WHEN 顧客がログアウトリクエストを送信したとき、システムはJWT CookieのMaxAgeを0に設定して削除しなければならない。

FR-AUTH-007: WHERE 未ログイン状態でもログアウトリクエストが送信された場合、システムは200 OKを返しJWT Cookieを削除しなければならない。

#### 5.1.3 新規登録

FR-AUTH-008: WHEN メールアドレスが未登録の新規顧客情報が送信されたとき、システムは顧客を登録し、パスワードをBCryptハッシュ化し、JWT Cookieを発行しなければならない。

FR-AUTH-009: WHEN 住所が都道府県名から始まる場合、システムは顧客登録を許可しなければならない。

FR-AUTH-010: WHERE 生年月日が任意項目である場合、システムはbirthday=nullで登録を許可しなければならない。

FR-AUTH-011: IF メールアドレスが既に存在する場合、THEN システムは409 Conflictエラーを返し、"指定されたメールアドレスは既に登録されています"というメッセージを表示しなければならない。

FR-AUTH-012: IF 住所が都道府県名から始まらない場合、THEN システムは400 Bad Requestエラーを返し、"住所は都道府県名から始めてください"というメッセージを表示しなければならない。

FR-AUTH-013: IF メールアドレス、顧客名、またはパスワードが空の場合、THEN システムは400 Bad RequestエラーとBean Validationエラーメッセージを返さなければならない。

#### 5.1.4 現在のログインユーザー情報取得

FR-AUTH-014: WHEN 有効なJWT Cookieを持つリクエストが/api/auth/meに送信されたとき、システムは現在ログイン中の顧客情報を返さなければならない。

FR-AUTH-015: IF JWT Cookieが設定されていない、または無効な場合、THEN システムは401 Unauthorizedエラーを返し、"認証が必要です"というメッセージを表示しなければならない。

### 5.2 書籍API（/api/books）

#### 5.2.1 書籍一覧取得

FR-BOOK-001: WHEN 書籍一覧取得リクエストが送信されたとき、システムは全書籍をカテゴリ、出版社、在庫情報とともに返さなければならない。

FR-BOOK-002: WHERE 書籍が0件の場合、システムは空配列を返さなければならない。

#### 5.2.2 書籍詳細取得

FR-BOOK-003: WHEN 有効な書籍IDが指定されたとき、システムは指定された書籍の詳細情報をカテゴリ、出版社、在庫情報とともに返さなければならない。

FR-BOOK-004: IF 指定された書籍IDが存在しない場合、THEN システムは404 Not Foundエラーを返し、"書籍が見つかりません"というメッセージを表示しなければならない。

#### 5.2.3 書籍検索

FR-BOOK-005: WHEN カテゴリIDが指定されたとき、システムは指定されたカテゴリに属する書籍一覧を返さなければならない。

FR-BOOK-006: WHEN キーワードが指定されたとき、システムは書籍名または著者名にキーワードを含む書籍一覧を部分一致で返さなければならない。

FR-BOOK-007: WHEN カテゴリIDとキーワードの両方が指定されたとき、システムはAND条件で書籍を検索しなければならない。

FR-BOOK-008: WHEN categoryId=0が指定されたとき、システムは全カテゴリから検索しなければならない。

FR-BOOK-009: WHERE パラメータが未指定の場合、システムは全書籍を返さなければならない。

FR-BOOK-010: WHERE 検索結果が0件の場合、システムは空配列を返さなければならない。

#### 5.2.4 カテゴリ一覧取得

FR-BOOK-011: WHEN カテゴリ一覧取得リクエストが送信されたとき、システムは全カテゴリをMapフォーマット（{"Java": 1, "JavaScript": 2, ...}）で返さなければならない。

### 5.3 注文API（/api/orders）

#### 5.3.1 注文作成

FR-ORDER-001: WHEN ログイン中の顧客が在庫ありの書籍を含む注文リクエストを送信したとき、システムは注文レコードを作成し、在庫を減算し、OrderResponseを返さなければならない。

FR-ORDER-002: WHEN 複数書籍を含む注文リクエストが送信されたとき、システムは複数の注文明細を作成し、各書籍の在庫を減算しなければならない。

FR-ORDER-003: WHEN 注文が作成されたとき、システムはORDER_TRAN、ORDER_DETAIL、STOCKの変更を単一トランザクションでコミットしなければならない。

FR-ORDER-004: IF 未ログインの場合、THEN システムは401 Unauthorizedエラーを返し、"認証が必要です"というメッセージを表示しなければならない。

FR-ORDER-005: IF 在庫数が注文数より少ない場合、THEN システムは409 Conflictエラーを返し、"在庫が不足しています: {bookName}"というメッセージを表示しなければならない。

FR-ORDER-006: IF カート追加時と注文時でversionが異なる場合（楽観的ロック競合）、THEN システムは409 Conflictエラーを返し、"他のユーザーが購入済みです。最新の在庫情報を確認してください。"というメッセージを表示しなければならない。

FR-ORDER-007: IF 複数書籍の注文で1冊でも在庫不足がある場合、THEN システムはトランザクションをロールバックし、全ての在庫減算を取り消さなければならない。

FR-ORDER-008: IF カート項目が空の場合、THEN システムは400 Bad RequestエラーとBean Validationエラーメッセージを返さなければならない。

#### 5.3.2 注文履歴取得

FR-ORDER-009: WHEN ログイン中の顧客が注文履歴取得リクエストを送信したとき、システムは当該顧客の注文履歴を注文日降順でソートして返さなければならない。

FR-ORDER-010: WHERE 注文履歴が0件の場合、システムは空配列を返さなければならない。

FR-ORDER-011: WHEN 1注文に複数明細が存在する場合、システムは注文明細ごとに1レコード（非正規化）で返さなければならない。

FR-ORDER-012: IF 未ログインの場合、THEN システムは401 Unauthorizedエラーを返し、"認証が必要です"というメッセージを表示しなければならない。

#### 5.3.3 注文詳細取得

FR-ORDER-013: WHEN 有効な注文IDが指定されたとき、システムは指定された注文の詳細情報を注文明細リスト（orderDetails）とともに返さなければならない。

FR-ORDER-014: IF 指定された注文IDが存在しない場合、THEN システムは404 Not Foundエラーを返し、"注文が見つかりません"というメッセージを表示しなければならない。

#### 5.3.4 注文明細取得

FR-ORDER-015: WHEN 有効な注文IDと明細IDが指定されたとき、システムは指定された注文明細を返さなければならない。

FR-ORDER-016: IF 指定された注文明細IDが存在しない場合、THEN システムは404 Not Foundエラーを返し、"注文明細が見つかりません"というメッセージを表示しなければならない。

### 5.4 画像API（/api/images）

#### 5.4.1 書籍表紙画像取得

FR-IMAGE-001: WHEN 有効な書籍IDが指定され、画像ファイルが存在する場合、システムはContent-Type: image/jpegで画像バイナリを返さなければならない。

FR-IMAGE-002: IF 画像ファイルが存在しない場合、THEN システムはフォールバック画像（no-image.jpg）を返さなければならない。

### 5.5 JWT認証フィルター

FR-JWT-001: WHEN 有効なJWT Cookieを持つリクエストが認証必須APIに送信されたとき、システムはAPIを正常に実行し、AuthenContextにcustomerIdを設定しなければならない。

FR-JWT-002: WHERE JWT不要なAPIにリクエストが送信された場合、システムは認証なしでAPIを実行しなければならない。

FR-JWT-003: IF JWT Cookieが設定されていない、または無効、または期限切れの場合、THEN システムは401 Unauthorizedエラーを返さなければならない。

### 5.6 配送料金計算

FR-DELIVERY-001: WHEN 購入金額が10,000円未満で配送先が沖縄県以外のとき、システムは配送料金を800円に設定しなければならない。

FR-DELIVERY-002: WHEN 購入金額が10,000円以上のとき、システムは配送料金を0円（無料）に設定しなければならない。

FR-DELIVERY-003: WHEN 配送先が沖縄県の場合、システムは特別配送料金（1,500円）を適用しなければならない。

---

### 5.7 トランザクション管理

FR-TXN-001: WHEN 注文処理が実行されたとき、システムはORDER_TRAN、ORDER_DETAIL、STOCKの変更を単一トランザクションで実行しなければならない。

FR-TXN-002: IF 注文処理中にエラーが発生した場合、THEN システムはトランザクションをロールバックし、データベースを変更前の状態に戻さなければならない。

---

### 5.8 並行制御（楽観的ロック）

FR-LOCK-001: WHEN カート追加時と注文時でversionが一致する場合、システムは在庫を減算し、versionをインクリメントしなければならない。

FR-LOCK-002: IF カート追加時と注文時でversionが異なる場合（他ユーザーが購入済み）、THEN システムは409 Conflictエラーを返し、トランザクションをロールバックしなければならない。

FR-LOCK-003: IF 複数書籍の注文で1冊でもversion不一致がある場合、THEN システムは全ての在庫減算をロールバックしなければならない。

NFR-AVAIL-002: システムは、JWT認証によるステートレス設計を実装しなければならない。

## 7. 外部インターフェース

### 7.1 customer-hub-api連携

EXT-CUST-001: WHEN 顧客情報が必要なとき、システムはcustomer-hub-apiのGET /customers/{customerId}を呼び出さなければならない。

EXT-CUST-002: WHEN ログイン処理中、システムはcustomer-hub-apiのGET /customers/query_email?email={email}を呼び出してメールアドレス検索を行わなければならない。

EXT-CUST-003: WHEN 新規顧客登録時、システムはcustomer-hub-apiのPOST /customers/を呼び出して顧客を登録しなければならない。

### 7.2 back-office-api連携

EXT-BOOK-001: WHEN 書籍一覧が必要なとき、システムはback-office-apiのGET /booksを呼び出さなければならない。

EXT-BOOK-002: WHEN 書籍詳細が必要なとき、システムはback-office-apiのGET /books/{bookId}を呼び出さなければならない。

EXT-BOOK-003: WHEN 書籍検索が必要なとき、システムはback-office-apiのGET /books/search/jpqlまたはGET /books/search/criteriaを呼び出さなければならない。

EXT-BOOK-004: WHEN カテゴリ一覧が必要なとき、システムはback-office-apiのGET /categoriesを呼び出さなければならない。

EXT-BOOK-005: WHEN 在庫情報が必要なとき、システムはback-office-apiのGET /stocks/{bookId}を呼び出さなければならない。

EXT-BOOK-006: WHEN 在庫更新が必要なとき、システムはback-office-apiのPUT /stocks/{bookId}を呼び出し、楽観的ロック対応を行わなければならない。

## 8. 前提条件・制約事項

### 8.1 前提条件

#### 8.1.1 技術前提

| 項目 | 内容 |
|------|------|
| JDK | 21以上 |
| Jakarta EE | 10 |
| アプリケーションサーバー | Payara Server 6.x |
| データベース | HSQLDB 2.7.x |
| ビルドツール | Gradle 8.x |

#### 8.1.2 データ前提

PRE-DATA-001: システムは、書籍マスタが事前に登録されていることを前提とする。

PRE-DATA-002: システムは、カテゴリマスタが事前に登録されていることを前提とする。

PRE-DATA-003: システムは、出版社マスタが事前に登録されていることを前提とする。

PRE-DATA-004: システムは、各書籍の在庫情報が登録されていることを前提とする。

#### 8.1.3 セキュリティ前提

PRE-SEC-001: システムは、JWT秘密鍵を環境変数で管理しなければならない（本番環境）。

PRE-SEC-002: システムは、JWT有効期限を24時間に設定しなければならない（設定可能）。

PRE-SEC-003: システムは、パスワードハッシュのコストをBCrypt cost=10に設定しなければならない。

### 8.2 制約事項

#### 8.2.1 技術的制約

CONST-TECH-001: システムは、サーバーサイドセッションを使用せず、ステートレス設計を実装しなければならない（水平スケーリング対応）。

CONST-TECH-002: システムは、初期リリースではJWT認証のみをサポートし、Basic認証、OAuth2は未対応とする（実装を簡素化）。

CONST-TECH-003: システムは、許可されたオリジンのみアクセス可能なCORS制限を実装しなければならない（セキュリティ対策）。

#### 8.2.2 機能的制約

CONST-FUNC-001: システムは、初期リリースでは決済方法の選択のみ実装し、実際の決済は未実装とする（外部連携は対象外）。

CONST-FUNC-002: システムは、初期リリースでは注文確認メール等のメール送信機能を未実装とする（外部連携は対象外）。

CONST-FUNC-003: システムは、初期リリースでは書籍・在庫・顧客の管理APIを未実装とする（顧客向け機能に集中）。
